## Metodología (cómo se audita esto)
- **Golden-record reconciliation:** la VERDAD (captura + chat) vs SIR (system of
  record), campo por campo. Cada campo: ✅ coincide · 🟡 parcial · ✗ falta/mal.
- **Baseline snapshot:** congelar los valores computados (abajo) para que un drift a
  futuro sea detectable — se re-corre la misma auditoría y se hace `git diff`.
- **"Si no se puede cambiar, se crea para poder cambiarlo":** cuando un campo no tiene
  edición manual (ej. contadores sociales, que salen de una captura), se CREA una
  observación corregida que se vuelve la fuente → así se puede corregir. (Feature
  pendiente: override manual de campos de perfil sin re-capturar.)
- **Agentes/metodología aplicables:** patrón de *reconciliación golden-record* +
  *snapshot de regresión*. Agentes tipo **Model QA Specialist** (auditoría end-to-end),
  **Reality Checker** (no aprobar sin evidencia), **Evidence Collector** (prueba visual).
  Limitación actual: la extensión de navegador está desconectada → la validación es a
  nivel dato+código, no clic-por-clic en la UI.
