# Auditoría SIR V2 — 2026-07-16

> Auditoría de cobertura end-to-end del sistema en producción. Ejecutada con agentes en paralelo + verificación del parent. Todo con evidencia real (no "health-check de fantasía").

## Metodología

Auditoría **de cobertura basada en riesgo** (estilo ISTQB smoke/sanity + exploratory charters):

1. **Inventariar** toda superficie del sistema (páginas, rutas API, bots, crons, integraciones, pipelines de datos) desde el código — no desde la memoria/docs.
2. **Por cada superficie**, definir un test concreto + resultado esperado.
3. **Ejecutar con evidencia real**: harness de sesión (login del test user `admin@cusmato.app` + cookie `@supabase/ssr` inyectada, contra PROD), webhooks sintéticos con el secret real (bots), y queries service-role a la DB (pipelines de datos, sobre el user real de Aaron).
4. **Registrar** PASS / FAIL / BLOCKED con la evidencia.
5. **Documentar** (este archivo) + separar hallazgos de humo.

Orquestación: 3 agentes en paralelo (superficie funcional · integraciones/bots/crons · pipelines de datos) + el parent probando los bots E2E y el pipeline dev.

## Hallazgos (lo que NO es verde)

1. **`ai_usage` congelada (2026-07-10) y 100% Anthropic — el ahorro OpenRouter no se ve aún.** Las rutas migradas a `complete()` no se ejercitaron en prod desde el deploy de esta sesión (Aaron no usó esas features), así que la telemetría no creció y no aparece `openrouter:...`. **NO es un bug**: el mecanismo está validado (smoke real de OpenRouter 200 + tests del router). Se confirmará el switch en cuanto se USE una ruta migrada (briefing, síntesis, decisión, etc.). *Acción: ninguna urgente; observar `ai_usage` tras uso real.*
2. **`learnings` vacía (Fase 3d).** La feature (tabla + `/api/learnings` + recall en el brief) existe y responde, pero nunca generó/guardó un learning. *Acción: verificar qué dispara la generación de learnings y si está cableada a correr.*
3. **`relationships` = 0 filas.** Vacía por diseño actual (la app usa people/observations). Consecuencia: el eje "estado de relación" del relationalScore no tiene data propia. *Acción: ninguna salvo que se quiera reactivar ese eje.*
4. **Push notifications sin VAPID.** `/api/push/vapid-public` → `configured:false`. Las push no funcionarían hasta setear la VAPID key. *Acción: setear VAPID en Vercel si/ cuando se quieran push.*
